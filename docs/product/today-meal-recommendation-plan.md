# “今天这顿吃什么”功能规划

## 1. 产品目标

为“不想规划整周，只想马上决定这一顿”的用户提供低门槛入口。系统结合长期偏好、菜品反馈与本次临时状态，一次生成 3 个可执行候选，并允许把选中方案继续沉淀到菜单、食谱和采购清单。

本功能是烟火食间家庭饮食闭环的即时入口，不扩展餐厅、外卖、地理位置或实时商家数据。

## 2. 首版范围

- 输入：餐次、人数、用餐场景、食欲/身体状态、可用时间、现有食材和本次备注。
- 记忆：复用“喜欢 / 不想再吃 / 做过了”结构化反馈；临时状态不覆盖长期偏好。
- 输出：首选、更省事、换个口味 3 个候选。
- 每个候选包含菜品、推荐理由、时间、难度、营养估算、食材、调料、步骤和注意事项。
- 操作：换一批、选择方案、加入今日菜单、进入采购清单。
- 降级：模型不可用或输出不合法时返回完整样例，并明确标记来源。

## 3. 交互流程

```text
首页 / 顶部导航
  -> 今天吃什么
  -> 填写少量当下条件
  -> 生成三个候选
  -> 选择一个方案
  -> 加入今日菜单
  -> 查看菜单或生成采购清单
```

## 4. 数据原则

- 长期偏好和菜品反馈参与推荐。
- 身体状态、现有食材和自由备注只随本次请求发送，不写入 Supabase。
- 模型配置继续只从浏览器临时随请求发送。
- AI 输出必须通过 Zod 校验。
- 推荐理由只能引用用户明确提供的条件和结构化记忆。
- 身体不适相关结果只作日常饮食参考，不提供诊断或治疗建议。

## 5. 验收标准

- 用户最多填写 6 类当下条件即可生成。
- 响应严格包含 3 个不同候选，且每个候选可转换为现有菜单结构。
- 忌口和“不想再吃”的菜品会传入生成约束。
- 选中候选后可在菜单页看到，并可由食材清单页读取。
- 桌面与移动端无横向溢出，按钮文字不被截断。
- `pnpm lint`、`pnpm build` 通过。

## 6. 后续评估

先观察即时推荐生成率、候选选择率、加入菜单率和进入采购清单率。只有核心闭环得到验证后，再评估库存识别、天气上下文或外出就餐模式。
